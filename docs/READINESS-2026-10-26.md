## 5. WAB

**What it is.** The Wallet Authentication Backend is "a Node.js/Express server built in TypeScript that provides a modular, extensible system for multi-factor user authentication. It manages 256-bit presentation keys for users" behind auth methods such as Twilio SMS, with a one-time faucet `[SRC]` `infra/wab/README.md:10-20`. The presentation key is one of three factors of the wallet's 2-of-3 root-key scheme (presentation, password, recovery), each pair unlocking the root primary key held in an on-chain UMP token `[SRC]` `infra/wab/how-it-works.md:9-36, 48-77`; "WAB server returns the final presentation key upon successful authentication" and the wallet's `WalletAuthenticationManager` uses it with the UMP system `[SRC]` `how-it-works.md:103-110`. It is `@bsv/wab-server` 1.8.10 on Node 24, Express, Knex over MySQL or SQLite, Twilio, OpenTelemetry `[SRC]` `infra/wab/package.json:1-51`; 49 non-test source files, 6,709 lines, 34 routes (`/auth/*`, `/account/delete/*`, `/user/*`, `/faucet/request`, `/share/*`, `/admin/*`, the `/demo` twins) `[SRC]` `infra/wab/src/app.ts:103-212`; ten migrations; rate limits per route family (`README.md:227-236`); an optional AES-256-GCM vault for presentation keys at rest (`README.md:198-225`); the faucet needs a funded toolbox wallet on a remote storage server (`README.md:272-277`).

**Whether a storage offer needs it.** No, for the storage wire: the storage server authenticates the wallet's identity key over BRC-104 and never sees a presentation key or a root key (section 2, row "BRC-103/104 auth"); the reference wires WAB only into `WalletAuthenticationManager` and `ShamirWalletManager`, not into `StorageServer` or `StorageClient` `[SRC]` `git grep WABClient edf6e03 -- packages/wallet/wallet-toolbox/src` (five files, none under `storage/`). Yes, if the offer is the Metanet client's sign-in as well as its storage: the browser UI library builds its wallet over remote storage with `DEFAULT_USE_WAB = true` against `https://wab.babbage.systems` `[SRC]` `bsv-stack-lean` `docs/readings/wallet.md:1206`, while the desktop wallet defaults `DEFAULT_USE_WAB` to false `[SRC]` `docs/readings/wallet.md:947`. The keeper's reading of 16:1xZ says the same: "a port is its own program, needed only if the offer is the Metanet-client sign-in as well as the storage".

**What a port would be.** Its own repository and captain under the keeper (the keeper's reading). On Cloudflare: one Worker with D1 (the ten migrations as D1 SQL), Twilio Verify over `fetch`, the rate limits as a binding, the vault with WebCrypto AES-GCM, the admin routes behind a secret, the faucet as a client of this storage server with its own funded identity, the demo accounts, the telemetry dropped for the platform's analytics. Size `[EST]`: 15 lane-days for the routes and the migrations with their witnesses, 3 for the faucet's wallet and its proof, 2 for the client-side conformance against the toolbox's `WABClient` (`packages/wallet/wallet-toolbox/src/wab-client/WABClient.ts`, `WABTransport.ts`, `WABResponseValidation.ts`, 41 KB at the pin). Not started; nothing in this repository depends on it.
